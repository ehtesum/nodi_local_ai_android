One architectural addition I'd recommend

Since your app combines a local LLM, encrypted storage, voice interaction, and an emotional companion, add a central AI Orchestrator module. Instead of letting the UI talk directly to the model, every request goes through the orchestrator, which decides:

whether the model needs memory,
whether a document search is required,
whether voice input should be transcribed,
how much context to include,
which model to use if multiple are installed,
whether the device has enough resources to process the request efficiently.

This keeps the system modular and makes it much easier to extend later with additional capabilities without tightly coupling every feature to the language model itself.

Instead of feeding only the user's text to the model, have your app maintain a lightweight state object, for example:

That state can be prepended to the prompt so the model naturally adapts its tone—for example, speaking more gently late at night or being more upbeat when the user is celebrating.

And a "Conversation Rules" block
Rules

- Never interrupt.

- Ask only one question at a time.

- If the user becomes emotional, reduce humor.

- If the user is excited, increase energy.

- If the user asks for technical help, become more structured.

- If the conversation becomes philosophical, slow down and explore ideas instead of rushing to conclusions.

- If silence occurs, never pressure the user to continue.

This kind of prompt tends to produce a companion that feels more consistent over long conversations, especially when running on a smaller local model (around 3B–8B parameters) where a strong, stable system prompt makes a noticeable difference.
